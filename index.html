Abstract


PDF documents integrate poorly with the web. To improve accessibility, they are frequently converted into HTML. Existing approaches for document-to-HTML conversion largely focus on retaining text and logical structure. However, the document's physical structure is not preserved — visual cues such as color and font style are overlooked, and design aspects such as content positioning are ignored.

To address these shortcomings, we introduce REPLICA, an agentic document-to-HTML framework that generates visually faithful, layout-aware, and semantically enriched HTML, which we refer to as Fid-HTML. Our approach generalises across diverse document types and multiple languages. For systematic evaluation, we introduce VFDR-Bench, spanning 15 languages and 15+ document types.

REPLICA achieves 93% visual fidelity, outperforming strong baselines including GPT-5 and Gemini 3 Pro. Notably, REPLICA with Qwen3-VL-8B achieves a 39% gain overall compared to Qwen3-VL-30B — despite being 3.75× smaller and operating at comparable inference time — highlighting the effectiveness of structured agentic design over brute-force scale. By preserving visual integrity and semantics in multilingual documents, REPLICA unlocks new possibilities for design-preserving translation, scalable access, and structured search.

Fid-HTML: High-Fidelity Document Representation. REPLICA encodes documents across six complementary dimensions to jointly preserve semantics and visual fidelity.

1

Textual Content

Complete text retained at both word and block level.

2

Hierarchical Structure

Nested <div> containers reflecting sections, subsections, and logical groupings.

3

Semantic Tags

Structured elements such as <li>, <table>, <tr>, <td> with meaningful class names.

4

Positional Information

Global placement via absolute positioning; local alignment via relative containers.

5

Styling Metadata

Font size, color, bold, italics, underline, and strikethrough preserved through inline CSS.

6

Figures & Backgrounds

Images and page-level backgrounds layered into the DOM with VLM-generated alt-text for accessibility.

Method

REPLICA employs a divide-and-conquer strategy across four coordinated stages

Overview of REPLICA. The agentic framework constructs a hierarchical semantic layout (1 Segment), generates sub-HTML fragments via routed specialist agents (2 Localize), composes them with position- and reading-aware assembly (3 Assemble), and iteratively refines visual fidelity through font optimisation, background restoration, and VLM-based reflection (4 Refine).

1
Segment

Builds a semantically grounded layout tree using an ensemble of flat, hierarchical, and text-segmentation models. A Labeling Agent uses Set-of-Mark prompting; a Grouping Agent constructs the layout graph.

2
Localize

A Router Agent validates each region and dispatches it to specialist agents (text, table, image, form, list, equation). Conditional tool invocation — OCR, table structure recognition — is used only when needed.

3
Assemble

A Position-Aware Merge tool performs bottom-up merging over the layout tree. A Reading-Order Agent evaluates textual continuity to compute a semantically grounded ordering relation.

4
Refine

Font-size optimisation, background restoration, and a closed-loop Reflection Agent that compares rendered HTML against the source document and injects targeted CSS corrections until convergence.

Agent & Tool Breakdown

🔵 Labeling Agent & Grouping Agent (Segment)

Assign semantic labels and construct nested layout trees from geometric proposals via Set-of-Mark prompting. Implemented with Qwen3-VL-8B-Instruct.

🟢 Router Agent & Specialist Agents (Localize)

The Router detects modality mismatches and overrides upstream labels. Six specialist agents handle text, tables, images, forms, lists, and equations — all Qwen3-VL-8B backbone.

🟡 Reading-Order Agent (Assemble)

Evaluates grammatical continuity and contextual coherence across block boundaries to autonomously correct spatial misalignments in complex multi-column layouts.

🔴 Reflection Agent (Refine)

Iteratively compares rendered HTML R(H) against the source document image, detecting perceptual artifacts such as overlap or wrapping inconsistencies. Runs up to 5 correction iterations.

Implementation Details

Segment: Doclayout-YOLO-v10 (flat), IndicDLP-YOLO-v10 (hierarchical), Hi-SAM (text segmentation). IoU-based ensemble fusion.

Localize: OCR via Gemma-3-4B-it · Word localisation via DocTR · Style extraction via TexTAR · Table grids via Surya TSR.

Assemble: Coordinate-based reading order with top-to-bottom, left-to-right column handling.

Refine: Font optimisation via textFit.js · Background inpainting via OpenCV · Reflection agent: Qwen3-VL-8B, max 5 iterations.

📐 Evaluation Metrics

TE: Character Recognition Rate (CRR) and Word Recognition Rate (WRR).

LS: Normalized Tree Edit Distance (NTED); TEDS for tables; CDM for formulas.

PS: Global Position Score (GPS) and Local Position Score (LPS) — new F1-based spatial metrics.

VF: Visual Fidelity Score (VFS) via VLM-as-a-judge on rendered HTML vs. ground truth.
